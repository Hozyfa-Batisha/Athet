## قاعدة البيانات

| الجدول              | المحتوى                                                       |
| ------------------- | ------------------------------------------------------------- |
| `users`             | الحساب والملف الشخصي وsalt/hash كلمة السر                     |
| `sessions`          | hash معرّف الجلسة، وCSRF token، وانتهاء الصلاحية              |
| `schedule_versions` | رقم نسخة لكل حساب، لمنع الكتابة من صفحة قديمة                 |
| `schedule_slots`    | خانة الجدول: اليوم والحصة والأسماء والتوقيت                   |
| `registrations`     | التسجيلات المؤرخة، والملاحظات، والمجموعات وأفرادها            |
| `user_settings`     | إعدادات الحساب وتقدم الألعاب                                  |
| `notifications`     | الإشعارات وحالة القراءة                                       |
| `audit_log`         | أحداث إنشاء الحساب والدخول والحفظ وتغيير كلمة السر والاستيراد |
| `schema_migrations` | migrations التي طُبقت                                         |
| `app_settings`      | علامات التهيئة والاستيراد مرة واحدة                           |

علاقات foreign keys تحذف السجلات التابعة للحساب عند حذفه. الفهارس موجهة للاستعلام حسب الحساب والتاريخ والاسم. تحتوي التسجيلات وخانات الجدول `extra JSONB` للاحتفاظ بالحقول الإضافية عند التطوير، مع بقاء الحقول الأساسية أعمدة فعلية. لا تُرسل كلمات السر المشفرة أو بيانات الجلسة الخاصة ضمن الملف الشخصي أو تصدير الحساب.

لا يحتوي الموقع على إدارة اشتراكات أو دفع أو صلاحية Admin جديدة. رسالة الترحيب الخاصة بالسبعة أيام موجودة كما في الموقع الأصلي؛ ليست نظام اشتراك يُنفّذ إغلاقًا تلقائيًا.

## واجهات API

كل طلب بيانات يتطلب جلسة. طلبات التعديل تتطلب أيضًا `X-CSRF-Token` الموجود في بيانات الصفحة و`GET /api/bootstrap`. يضيفه كود الواجهة تلقائيًا. لا تمرر معرف حساب من العميل؛ يحدد السيرفر الحساب من الجلسة.

| الطلب                          | الوظيفة                                                        |
| ------------------------------ | -------------------------------------------------------------- |
| `GET /api/me`                  | الملف الشخصي العام للحساب الحالي                               |
| `POST /api/profile`            | `{name, phone}`                                                |
| `POST /api/avatar`             | `{image}` بصيغة JPEG/PNG/WebP data URI، أو سلسلة فارغة للإزالة |
| `POST /api/password`           | `{old, pass}` وإغلاق بقية جلسات الحساب                         |
| `GET /api/schedule`            | `{schedule, students, revision}`                               |
| `POST /api/schedule`           | إرسال الشكل نفسه مع `revision` الحالي؛ يرجع `409` عند التعارض  |
| `GET /api/settings`            | إعدادات الحساب                                                 |
| `PATCH /api/settings`          | `{changes: {key: stringValue}}`، أو `null` لحذف مفتاح          |
| `GET /api/notifications`       | إشعارات الحساب                                                 |
| `POST /api/notifications/read` | `{ids: [...]}` لتعليم القراءة                                  |
| `GET /api/bootstrap`           | الملف الشخصي والإعدادات والإشعارات وCSRF للصفحة الحالية        |
| `GET /api/export`              | تنزيل بيانات الحساب الحالي بصيغة JSON                          |
| `POST /api/backup-now`         | إرسال اختياري إلى تيليجرام بعد تهيئته                          |
| `POST /logout`                 | إنهاء الجلسة الحالية                                           |
| `GET /healthz`                 | فحص اتصال قاعدة البيانات، دون بيانات الحسابات                  |

مفاتيح الإعدادات الحالية: `theme`، `hurufi-theme`، `hurufi-muted`، `hurufi-progress-v1`، `hurufi-arcade-v1`، `qsrcid`، `quran-options`. الحفظ جزئي حسب المفاتيح، فلا يستبدل تغيير المظهر تقدم اللعبة. المظهر مشترك بين الموقع والألعاب. تحديث تقدم اللعبة نفسها من جهازين في الوقت نفسه يستخدم آخر حفظ لهذا المفتاح؛ حماية revision تخص جدول الحصص والتسجيلات.

## تطوير آمن على نفس المخرجات

- احتفظ بـIDs وواجهات الدوال المرتبطة بأزرار HTML أثناء التعديل حتى تبقى الأحداث سليمة.
- قواعد CSS الخاصة بالهاتف واللمس والاتجاه الأفقي والسبورة بقيت من المصدر نفسه.
- ملفات منطق الألعاب المورّدة كانت bundle بالفعل؛ فُصلت وفُك تنسيقها، مع الاحتفاظ بخوارزمياتها. لا تُعد كتابة منطق لعبة كاملة لازمة لإضافة ميزة للموقع.
- لا تعدّل migration طُبقت بالفعل؛ أضف ملف SQL جديدًا برقم أعلى.
- استخدم parameters `$1` وما بعدها، واستخدم `db.transaction` عندما تعتمد استعلامات على بعضها.
- لا تضف بيانات حسابات أو مفاتيح سرية داخل `public/` أو كود الواجهة.

المراجع: [node-postgres queries](https://node-postgres.com/features/queries)، [transactions](https://node-postgres.com/features/transactions)، [PostgreSQL constraints](https://www.postgresql.org/docs/current/ddl-constraints.html).
