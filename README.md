# أثر — نسخة السيرفر المنظمة

نفس موقع أثر وأقسامه: جدول الحصص، سجل الطلاب والمجموعات، حصاد الشهر، السبورة، القرآن، بطاقات الحروف والألعاب. تم الاحتفاظ بالتصميم وقواعد تنسيق الهاتف، وفصل الواجهة عن السيرفر وملفات الصور والصوت.

## ما الذي تغير؟

- **Frontend:** صفحات HTML، وملفات CSS وJavaScript مقسمة حسب الوظيفة، وملفات مستقلة لصور الحروف والمصحف والصوت والخطوط المضمّنة.
- **Backend:** Node.js 24، وواجهات API، وطبقات مستقلة للمسارات والتحقق والخدمات والتعامل مع قاعدة البيانات.
- **Database:** PostgreSQL، بجداول للحسابات والجلسات والجدول وتسجيلات الطلاب والإعدادات والإشعارات وسجل التعديلات، مع migrations قابلة للإضافة.
- الحصص والملفات الشخصية والإشعارات والمظهر واختيار القارئ وتقدّم الألعاب تُحفظ على السيرفر حسب الحساب. لا يستخدم كود الموقع localStorage أو sessionStorage أو IndexedDB.
- كوكي الدخول الوحيدة `sid` مؤقتة، وHttpOnly وSameSite=Strict، وتصبح Secure عند تشغيل الموقع عبر HTTPS. أزيل خيار «تذكّرني ٣٠ يوم» حتى لا ينشئ الموقع كوكي دخول دائمة. البيانات المعروضة تكون في ذاكرة الصفحة أثناء استخدامها.
- الحفظ متسلسل، ومعه رقم نسخة يمنع صفحة قديمة من الكتابة فوق تعديل أحدث للجدول. تظهر رسالة واضحة إذا فشل الحفظ، مع إمكانية إعادة المحاولة. عند انقطاع الاتصال لا تُحفظ نسخة على جهاز الزائر.
- تم إصلاح اختلاف `Games` و`games` على Linux، وإخراج الألعاب من الصفحة المضمّنة إلى صفحات وملفات فعلية. Tailwind وTone موجودان ضمن ملفات الموقع، فلا يحتاج تحميلهما من CDN.

## متطلبات الاستضافة

استضافة تدعم **Node.js 24 وPostgreSQL**، أو سيرفر يشغّل **Docker Compose**. استضافة HTML ثابتة أو GitHub Pages أو استضافة PHP فقط لا تشغّل الباك إند الموجود هنا.

## التشغيل باستخدام Docker Compose

من داخل مجلد المشروع، أنشئ الإعدادات. إذا كان Node.js موجودًا، استخدم الأمر التالي بعد استبدال الدومين:

```bash
node scripts/setup-env.js https://your-domain.example
docker compose up -d --build
docker compose logs --tail=100 app
```

الأمر الأول يُنشئ `.env` بكلمة سر عشوائية لقاعدة البيانات، ولا يكتب فوق ملف موجود. إذا كنت تستخدم Docker فقط، انسخ `.env.example` إلى `.env` وعدّل `PUBLIC_URL` و`COOKIE_SECURE` و`POSTGRES_PASSWORD` و`DATABASE_URL`. استخدم كلمة سر طويلة عشوائية من حروف وأرقام hexadecimal حتى لا تحتاج ترميزها داخل رابط قاعدة البيانات.

```bash
cp .env.example .env
docker compose up -d --build
```

الخدمة متاحة على `127.0.0.1:3000` داخل السيرفر، وقاعدة البيانات ليست مكشوفة على الإنترنت. اربط الدومين بها عبر Nginx أو لوحة الاستضافة، وفعّل HTTPS. يوجد مثال HTTP لـNginx في `deploy/nginx.conf`؛ أضف إعداد الشهادة بالطريقة المعتادة عندك. يجب أن يطابق `PUBLIC_URL` الدومين والبروتوكول الفعليين، لأن السيرفر يتحقق من مصدر طلبات التعديل.

للتجربة على نفس الجهاز يمكنك استخدام `http://localhost:3000` مع `COOKIE_SECURE=false`.

## التشغيل على استضافة Node.js وقاعدة بيانات موجودة

1. أنشئ قاعدة PostgreSQL ومستخدمًا خاصًا بالتطبيق.
2. انسخ `.env.example` إلى `.env`، واضبط `DATABASE_URL` و`PUBLIC_URL`. إذا كانت قاعدة البيانات البعيدة تشترط TLS فاضبط `DATABASE_SSL=true` واستخدم شهادة موثوقة.
3. نفّذ:

```bash
npm ci --omit=dev
npm run migrate
npm start
```

السيرفر يطبّق migrations الناقصة عند بدء التشغيل أيضًا. ملفات CSS الجاهزة موجودة داخل `public/`؛ لا يحتاج تشغيل نسخة الإنتاج تثبيت أدوات التطوير أو إعادة البناء. استخدم مدير عمليات الاستضافة أو systemd لتشغيل التطبيق بعد إعادة تشغيل السيرفر. اجعل **مجلد المشروع** هو working directory.

## إدارة الحسابات وVIP

صفحة `/admin` مخصصة لحساب المدير. تعرض الحسابات وآخر دخول وعدد زيارات اليوم، وتتيح تفعيل VIP حتى تاريخ محدد أو إيقافه. يظهر شعار VIP بجانب صورة الحساب المشترك، ويسقط تلقائيًا بعد انتهاء التاريخ.

في قاعدة بيانات جديدة، أول حساب يُنشأ من `/setup` هو حساب المدير. إذا كانت قاعدة البيانات تحتوي حسابات بالفعل، أنشئ حساب مدير مستقلًا من الطرفية بالأمر `npm run admin:create -- اسم-المدير`. سيطلب كلمة المرور دون إظهارها. عند التشغيل المحلي عبر `start.bat`، أغلق نافذة الموقع قبل تنفيذ الأمر حتى يستخدم نفس قاعدة البيانات المحفوظة، ثم افتح الموقع مجددًا. لا ترسل كلمة المرور في رابط أو رسالة.

حساب المدير مخصص للوحة الإدارة، وتظل حسابات المعلمين والطلاب العادية تدخل الموقع كما كانت. التحديث يضيف الجداول والأعمدة اللازمة تلقائيًا عند تشغيل السيرفر.

## حماية تسجيل الدخول

بعد خمس محاولات فاشلة لنفس الاسم والاتصال، ينتظر الزائر 30 ثانية قبل إعادة المحاولة. تزداد المدة تدريجيًا حتى 15 دقيقة، وتظل محفوظة عند إعادة تشغيل السيرفر. يظهر وقت الانتظار في صفحة الدخول، ويمسح الدخول الناجح عدّاد المحاولات. يوجد أيضًا حدّ عام للمحاولات من نفس الاتصال. كلمات المرور الجديدة تُخزَّن بتكلفة scrypt أقوى، وتستمر كلمات المرور القديمة في العمل حتى يغيرها أصحاب الحسابات. يبدأ الحد الأدنى لكلمات المرور الجديدة من 10 حروف.

إذا كان السيرفر خلف Nginx، اضبط `TRUST_PROXY=true` فقط بعد التأكد أن التطبيق غير مكشوف مباشرةً للإنترنت وأن Nginx يرسل `X-Forwarded-For` من عنوان الزائر الحقيقي. ملف `deploy/nginx.conf` يضبط ذلك. عند التشغيل المباشر اترك الإعداد `false`.

## بياناتك القديمة

مجلد `legacy-data/` يحتوي نسخة خاصة من الحسابات وملفات الحصص الموجودة في الملف الذي أرسلته. عند أول تشغيل، ينقلها السيرفر إلى PostgreSQL مرة واحدة داخل transaction. يمكنك تسجيل الدخول بنفس أسماء المستخدمين وكلمات السر القديمة. يتم حفظ hashes القديمة، ولا تُحوّل كلمات السر إلى نص مكشوف.

لا تُنقل جلسات الدخول القديمة؛ سجّل الدخول من جديد. ولا تُنسخ مفاتيح تيليجرام أو ملفات Git أو نسخ HTML القديمة إلى النسخة الجديدة. لم تتغير الملفات الأصلية التي أرسلتها.

بعد التأكد من ظهور حساباتك وطلابك، اضبط `IMPORT_LEGACY_ON_START=false`. تستطيع الاحتفاظ بنسخة خاصة من `legacy-data/` خارج مجلد النشر، ثم إفراغ محتواه من نسخة السيرفر. اترك المجلد نفسه موجودًا إذا كنت ستعيد بناء صورة Docker.

لنقل ملفات من تثبيت قديم آخر قبل أول استيراد:

```bash
npm run import:legacy -- /absolute/path/to/old/ather
```

الاستيراد يرفض الملفات التالفة أو تعارض أسماء المستخدمين، ويرجع العملية كلها دون استيراد جزئي. الإشعارات والمظهر وتقدّم الألعاب القديمة التي كانت موجودة في متصفحات الزوار ليست ضمن الملف المرفوع؛ تبدأ بإعداداتها الافتراضية، وتُحفظ التغييرات الجديدة في قاعدة البيانات.

**مهم للنشر:** الجذر العام للموقع هو `public/` فقط، وطلبات الزوار تمر عبر سيرفر Node. لا تجعل مجلد المشروع كله مجلدًا عامًا في Apache أو Nginx، لأنه يحتوي مدخلات استيراد وإعدادات خاصة.

## النسخ الاحتياطي

لنسخة كاملة من قاعدة البيانات في تشغيل Docker:

```bash
sh scripts/backup.sh
```

تظهر النسخة داخل `backups/`. استعادة نسخة تختارها، بعد إيقاف التطبيق:

```bash
docker compose stop app
docker compose exec -T db pg_restore -U athar -d athar --clean --if-exists --no-owner --single-transaction < backups/your-backup.dump
docker compose start app
```

استعادة النسخة تستبدل بيانات القاعدة الحالية بمحتوى النسخة. لم تتم جدولة نسخ احتياطية أو إرسال أي شيء تلقائيًا. يمكن إضافة جدول للنسخ عبر لوحة السيرفر لاحقًا.

لتحميل نسخة JSON من بيانات الحساب الحالي، افتح `/api/export` وأنت مسجّل الدخول. هذه نسخة حساب للتصدير والمراجعة؛ لا يوجد زر لاستعادة JSON داخل الواجهة. الاستعادة الكاملة المدعومة هنا تستخدم `pg_dump` و`pg_restore` كما سبق.

دعم النسخ إلى تيليجرام اختياري: اضبط `TELEGRAM_BOT_TOKEN` و`TELEGRAM_CHAT_ID` في `.env`، ثم أعد تشغيل التطبيق. الإرسال لا يحدث إلا بطلب POST صريح إلى `/api/backup-now` من حساب مسجل، مع CSRF token. لا توجد عملية إرسال تلقائية مفعّلة. النسخة تخص الحساب الذي طلبها، ولا ترسل حسابًا آخر.

## التطوير وإضافة ميزات

```bash
npm ci
npm run check
npm test
npm run build:css
```

بنية المشروع وتفاصيل API في [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md)، وسجل التغييرات والتحقق في [docs/CHANGES.md](docs/CHANGES.md).

عند تعديل أصناف Tailwind في HTML أو JavaScript، أعد تنفيذ `npm run build:css`. إضافة ميزة جديدة تتم من خلال module للواجهة، ومسار API، وخدمة أو repository، وmigration جديدة إن لزم؛ لا تحتاج إعادة جمع الموقع في ملف HTML واحد.

اختبارات التكامل تستخدم PGlite لتشغيل SQL على محرك PostgreSQL مضمّن مع بيانات وهمية. **الإنتاج يستخدم PostgreSQL عبر pg**؛ التشغيل بخيار `DB_DRIVER=pglite` مرفوض عندما تكون `NODE_ENV=production`.

تظل Google Fonts والتلاوات الخارجية وواجهة Quran.com بحاجة إلى الإنترنت كما في الأصل. التسجيلات وموارد الألعاب المرفوعة موجودة ضمن المشروع. حافظت النسخة على مصادر النصوص والروابط الظاهرة في الموقع.

للمعاينة أثناء التطوير فقط، شغّل `npm run dev`. يفتح هذا الأمر عرضًا تجريبيًا بحساب وبيانات وهمية في قاعدة مؤقتة في الذاكرة، دون استيراد حساباتك أو طلب بيانات دخولك. التعديلات التجريبية تُفقد عند إغلاقه. **الإنتاج يشغّل `npm start`**، ولا يشغّل ملف العرض التجريبي.
